# 승인 체크리스트 v1 · 2회차

> 오늘 바뀐 점 (2026-10-06)
> 1. "충분한가 · 지나치게 · 심각한 · 적절하게" 같은 판단형 항목 4개를 예/아니오로 답하는 문장으로 바꿨다.
> 2. 테스트는 "새 public 메서드마다 직접 호출하는 테스트 1개 이상(접근자 제외)", 치명은 4종으로 못박고, 경고도 1건 이상이면 반려한다(치명은 긴급 조치 · 전체 재검증, 경고는 해당 이슈만 재확인).
> 3. 범위 밖 변경은 같은 파일 import 정리만 허용하고, 컨벤션은 반려 항목(계층 · 빈 catch · 임시 출력)과 경고 등급 항목(네이밍 등)으로 나눴다.

버전: v1 (팀 기준 반영). 이전 판(v0)은 git 이력에 있다.
AI 가 만든 변경분 · 외주사 PR 을 머지하기 전에 리뷰어가 대조하는 목록이다. 네 기준이 **모두** 충족되고 **경고가 0건**이어야 승인이다. 하나라도 어긋나면 반려.

## 심각도 정의

- **치명** — §2 의 네 종류(비밀값 노출 · 데이터 손실 · 인증 우회 · SQL 문자열 조립)만 치명이다. 1건이라도 있으면 반려하고, 긴급 조치(노출된 비밀값 교체, 이미 반영된 변경 되돌리기)를 함께 요청한다. 다시 제출되면 처음부터 전부 재검증한다.
- **경고** — 네 종류에 해당하지 않지만 팀 `CLAUDE.md` 의 규칙을 어기거나 다음 변경에서 사고가 될 수 있는 문제. 1건이라도 있으면 반려한다. 긴급 조치는 없고, 다시 제출되면 지적한 이슈가 고쳐졌는지와 테스트만 확인해 재판정한다.
- **제안** — 더 나은 방법이 있다는 의견. 승인 · 반려에 영향을 주지 않는다. 목록으로만 남긴다.

이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향 네 항목으로 적는다. 근거 줄번호를 댈 수 없는 지적은 "확인 필요"로 따로 둔다.

## 1. 테스트 통과

- [ ] 변경된 모듈의 테스트 명령을 실제로 실행했다(실행하지 않고 통과라고 쓰지 않는다).
- [ ] 실행 결과에 실패 · 오류가 0건이다.
- [ ] 이번 변경에서 새로 생기거나 시그니처가 바뀐 public 메서드(컨트롤러 핸들러 포함)마다 그 메서드를 직접 호출하는 테스트가 1개 이상 있다. getter · setter · 생성자 · record 접근자는 제외한다.
- [ ] 기존 테스트를 지우거나 건너뛰게(`skip`, `@Disabled`) 바꾼 곳이 없다.

CLAUDE.md 의 "새 엔드포인트 · 새 public 서비스 메서드마다 테스트" 규칙은 이 절에서만 본다. §4 컨벤션에서 다시 세지 않는다.

## 2. 치명 이슈 0건

- [ ] **[비밀값 노출]** 비밀번호 · 토큰 · 키가 코드 · 설정 · 테스트 픽스처 · 로그 인자에 리터럴로 들어 있지 않다(실습용 `app-pass` 제외).
- [ ] **[데이터 손실]** 새로 생긴 DELETE · UPDATE · TRUNCATE · DROP 문이나 덮어쓰기 코드가 모두 요청 문장에 적혀 있다.
- [ ] **[인증 우회]** 인증 · 권한 검사를 지우거나 조건을 완화한 곳이 없고, CORS 허용 범위(`/api/**` · `http://localhost:5173` · GET)를 넓힌 곳이 없다.
- [ ] **[SQL 문자열 조립]** SQL 을 `+` · `String.format` · `concat` · `StringBuilder` 로 만드는 곳이 없다(파라미터 바인딩 사용).

## 3. 요청 범위 이탈 없음

- [ ] 요청 문장이 한 문장으로 확인되었다(없으면 판정하지 않고 먼저 묻는다).
- [ ] 변경 파일 목록의 모든 파일이 요청 문장으로 설명된다.
- [ ] 요청 문장으로 설명되지 않는 변경 hunk 는 같은 파일 안의 import 정리(추가 · 삭제 · 순서)뿐이다. 리팩토링 · 메서드 추출 · 로그 문구 변경 · 포맷팅은 "동작 변화 없음"이어도 범위 밖이다.
- [ ] 의존성 추가 · DB 스키마 변경 · 설정 파일 변경이 있다면 요청에 포함돼 있었다.

## 4. 컨벤션 준수

- [ ] 팀 `CLAUDE.md` 의 코딩 컨벤션과 금지 사항을 대조했다(`convention-check` Skill 이 있으면 그 결과를 쓴다).

반려 항목(1건이라도 있으면 이 기준 미충족)

- [ ] **[계층]** 컨트롤러에 Repository · `JdbcTemplate` 필드 · 생성자 인자, SQL 문자열이 없다.
- [ ] **[계층]** 서비스가 다른 도메인의 Repository 를 주입받지 않는다.
- [ ] **[빈 catch]** 모든 `catch` 블록이 로그를 남기고 다시 던지거나 도메인 예외로 바꿔 던진다.
- [ ] **[임시 출력]** `System.out` · `System.err` · `printStackTrace()` · `console.log` 가 없다.

반려(경고 등급) 항목 — 이슈 목록에 경고로 적고, 경고 0건 조건에 따라 반려한다

- [ ] 클래스 · 메서드 · 필드 · 상수 이름이 CLAUDE.md 네이밍 규칙(`PascalCase` · `camelCase` · `UPPER_SNAKE_CASE` · 약어 첫 글자만 대문자)을 따른다.
- [ ] 위 반려 항목 밖의 CLAUDE.md 컨벤션 · 금지 사항 위반(인자 없는 `now()`, 숫자 리터럴 규칙값, `@Transactional` 안의 데이터 크기 비례 루프, 120자 초과 등)을 모두 경고로 적었다.

## 판정 형식

첫 줄에 `판정: 승인` 또는 `판정: 반려`. 이어서 네 기준의 충족 · 미충족과 경고 건수 표, 그다음 이슈 목록(심각도 · `파일:줄번호` · 근거 · 수정 방향). 코드는 수정하지 않는다.
