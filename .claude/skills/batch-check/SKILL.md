# 배치 점검

## 입력
- 로그 폴더: `$ARGUMENTS`. 비어 있으면 `pipeline-samples/batch-logs`.
- 건수 CSV: 로그 폴더의 상위 폴더에 있는 `datamart-counts.csv` (`date,job,row_count,loaded_at`). 없으면 멈추고 경로를 묻는다.

## 점검 기준
1. 실행 여부: 다른 날에는 매일 돌던 job 이 그날 로그에 없거나, START 만 있고 SUCCESS · 종료 기록이 없으면 이상.
2. 중복 실행: 같은 날 같은 job 의 SUCCESS 가 두 번 이상이면 이상.
3. 적재 건수: 그 job 의 직전 7일(CSV 직전 행 최대 7개) 평균에서 ±30% 넘게 벗어나면 이상. 0건은 무조건 이상. 이전 데이터가 없는 날은 판정하지 않았다고 적는다.
4. 지연: START~SUCCESS 소요 시간이 그 job 의 다른 날 중앙값의 2배를 넘으면 이상.

## 작업 규칙
- 로그를 통째로 읽지 않는다. `grep -n` · `awk` · `wc` 로 필요한 줄만 뽑는다.
- 평균 · 편차 · 배수 · 합계는 암산하지 않는다. 명령이나 스크립트로 계산하고, 스크립트는 scratchpad 에 둔다.
- 근거 표기: 로그는 `파일명:줄번호` 에 해당 필드(`status=`, `elapsed=`, `rows=`)를 붙인다. 건수는 `CSV N행` 과 그 행 값을 적는다.
- 로그에 없는 원인은 추측하지 않는다. 원인은 "확인 필요"로 두고, 무엇을 더 봐야 하는지만 적는다.
- 학생 식별자(`STU-…`) · 이메일 · 토큰은 리포트와 답변에 옮기지 않는다.

## 리포트
- 이상이 한 건도 없으면 파일을 만들지 않고 "이상 없음" 한 줄만 답한다.
- 이상이 있으면 `docs/batch-check/report.md` 에 저장한다. 파일이 이미 있으면 덮어쓰기 전에 묻는다.
- 형식:
  1. 맨 위 요약 한 줄: 점검 기간, 이상 건수
  2. 이상 목록 표: 날짜 / job / 점검 항목 / 근거 / 영향 추정 / 다음 확인 사항
     - 영향 추정은 로그 · CSV 에서 읽히는 범위만 쓰고 "(추정)"이라고 표시한다.
  3. 맨 아래: "이상 없음으로 판정한 날짜" 목록
- 네 기준에 해당하지 않는 반복 WARN 은 표에 넣지 않고 참고로 한 줄만 적는다.
