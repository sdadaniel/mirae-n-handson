# 장애 RCA 리포트

대상은 `incident-logs/$ARGUMENTS/` , 결과는 `docs/rca/$ARGUMENTS.md` 다.
리포트를 저장하기 전에 `.claude/skills/rca/masking-rules.md` 의 규칙을 적용한다.

## 절차

### 1. 수집 범위
- 파일을 통째로 읽지 않는다. `wc -l` · `head` · `tail` · `grep -c` · `grep -n` · `sed -n` · `awk` 로 필요한 줄만 본다.
- 파일마다 줄 수 · 기록 기간 · 시각 형식 · 타임존을 표로 적는다. 오프셋이 없는 파일은 다른 파일과 같은 사건을 맞춰 타임존을 판단하고 근거를 적는다. 시각은 KST 하나로 통일한다.
- WARN/ERROR · 5xx 등 이상 줄을 분 단위로 집계해 이상 구간과 앞뒤 기준선(버퍼)을 정한다. 이 단계에서는 원인을 말하지 않는다.
- 사용한 집계 명령을 리포트에 남긴다.

### 2. 타임라인
- 모든 줄에 출처 `파일:줄번호` 를 단다. 범위는 `a~b`, 나열은 `·`.
- 반복 메시지는 첫 발생 줄 + 분당 건수로 적는다. 원문 발췌는 80자 이내.
- 파일마다 시각 정밀도가 다르므로 다른 파일의 사건이 같은 초 안에 있으면 **(선후 불확실)** 로 표시한다.
- "이 로그로 확인할 수 없는 것"을 따로 적는다.

### 3. 가설
- 증상(오류 메시지)과 원인을 나눈 뒤, 서로 다른 계층(코드 · DB · 트래픽 · 인프라 등)에서 가설을 **2개 이상** 세운다.
- 가설마다 지지 근거(타임라인 줄), **반증 조건**(무엇이 보이면 틀린 가설인가), 확인 방법(실행할 명령)을 적는다.

### 4. 반증 · 판정
- 먼저 로그로 반증을 시도한다. 확인 명령을 실제로 실행하고 결과를 실행 기록으로 남긴다.
- 살아남은 가설은 코드 · 설정과 대조한다(`modern/api` 소스, `application.yml` 등). 로그 단서 → 코드 위치를 `파일:줄번호` 로 잇는다.
- 가설마다 **채택 · 기각 · 유지 · 판단 불가(로그 부족)** 중 하나로 판정하고 이유를 적는다. 판단 불가면 필요했던 로그를 적는다.
- 확신 수준(높음 · 중간 · 낮음)과 측정하지 못한 부분을 함께 밝힌다.

### 5. 리포트 작성
`docs/rca/$ARGUMENTS.md` 에 다음 순서로 쓴다.
1. 요약 — 언제 · 영향 · 원인 · 확신 수준 · 즉시 수정
2. 수집 범위 · 타임라인 · 가설과 검증(1~4단계 결과)
3. 원인 — 직접 원인(인과 순서)과 배경 원인
4. 근거 로그 줄 — 원인 문장마다 `파일:줄번호` 와 발췌
5. 수정안 — 지금 적용할 변경(파일 · 위치 · 내용)
6. 재발 방지 — 같은 구조가 다시 들어오지 못하게 할 장치
7. 모니터링 항목 — 지표 · 임계값 · 이번에 몇 분 일찍 알 수 있었는지
8. 확인하지 못한 것 — 이유와 다음을 위해 남겨야 할 로그

### 6. 마스킹 후 저장
- `masking-rules.md` 를 적용한 뒤 저장하고, 리포트 끝에 종류별 마스킹 건수를 한 줄로 적는다.

## 하지 말 것
- 로그에 없는 줄을 인용하지 않는다. 인용한 줄번호는 `sed -n` 으로 다시 확인한다.
- 가장 많이 나온 오류를 곧바로 원인이라고 부르지 않는다. 처음 나온 이상 신호와 인과 순서로 판단한다.
- 원본 로그와 소스 코드를 수정하지 않는다. 수정안은 리포트에만 적는다.
- 마스킹 대응표(원본 값 ↔ 별칭)를 파일로 남기지 않는다.
- 마스킹 전 원본을 임시 폴더에 복사해 두지 않는다.
