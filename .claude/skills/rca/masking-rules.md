# RCA 리포트 마스킹 규칙

리포트(`docs/rca/*.md`)를 저장하기 전에 본문 · 표 · 발췌 · 명령 예시 전체에 적용한다. 원본 로그는 고치지 않는다.

| 대상 | 규칙 | 예 |
|---|---|---|
| IP (구분 필요) | 분석에서 서로 구분해야 하는 IP 는 역할 별칭으로 바꾼다. 별칭은 역할 + 순번(등장 순)으로 짓는다 | `API-1`, `API-2`(upstream 앱 서버), `교사단말A~D`(클라이언트, 첫 요청 순) |
| IP (그 밖) | 앞 두 옥텟만 남긴다 | `10.20.x.x` |
| 이메일 | 값 전체를 가린다 | `[EMAIL]` |
| 학생 식별자 | `STU-<숫자>` 는 가린다. 발췌에는 아예 넣지 않는 것을 우선한다 | `[STU]` |
| 토큰 · 세션 · API 키 | `Bearer …`, `token=…`, 쿠키 값 등 값 부분을 가린다 | `Bearer [TOKEN]` |
| 비밀번호 · 접속 문자열 | 비밀번호, `-p<값>`, JDBC URL 의 계정 · 비밀번호, slow log 의 접속 사용자@호스트를 가린다 | `-p[SECRET]`, 접속 `[SECRET]` |

## 별칭 규칙
- 별칭의 뜻은 리포트의 "읽는 법" 절에 역할로 정의한다(예: "API-1 = 장애 중 타임아웃이 난 upstream 앱 서버"). 원래 값은 적지 않는다.
- 같은 값은 리포트 전체에서 같은 별칭을 쓴다. 대응은 작업 중에만 기억하고 파일로 남기지 않는다.

## 저장 전 확인
- 저장할 리포트에서 IPv4 · 이메일 · `STU-[0-9]` · `Bearer` · `password` · `-p` 뒤 값 패턴을 `grep` 해 0건인지 확인한다.
- 리포트 끝에 건수를 적는다: `마스킹 적용: IP N건 · 이메일 N건 · 학생 식별자 N건 · 토큰 N건 · 비밀번호 · 접속 문자열 N건`
